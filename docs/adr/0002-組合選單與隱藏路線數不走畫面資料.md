# 0002 組合選單與隱藏路線數不走畫面資料

## 背景

到站更新（`updater.js`）把畫面資料交給 `app.js` 的 `render(v)` 畫出看板。但看板上方的組合選單、名稱下方的原因（「通常這個時間用這組」）、站牌路線圖，以及清單下方的「已隱藏 N 條路線」，是由 `renderChips()`、`renderHidden()` 畫的。它們自己讀目前組合（`store.current()`）和第幾段（`updater.leg()`），沒有經過畫面資料。

`render(v)` 只在換組合或換段時呼叫 `renderChips()`。另外還有幾個地方會直接呼叫它：打開選單看過提示、從設定頁回看板、離開後回來被自動換組合、App 啟動、點「已隱藏 N 條」。

程式審查和第三輪架構檢視都把這點列為「畫面有兩個資料來源」。

## 決定

維持現狀，組合選單、名稱下方原因、已隱藏路線數不併進畫面資料。

## 理由

- 目前沒有因為這兩個來源而出錯的 bug。上述呼叫時機都在目前組合、第幾段或提示狀態改變之後，那時兩個來源讀到的值相同。
- 如果要併進畫面資料，到站更新就得知道組合清單和使用習慣的猜測結果（名稱下方原因）。到站更新會因此多認識兩件不屬於它的事，和「不管使用習慣」的分工衝突。
- 收益只有「render 一次畫完」，換來的是 interface 變寬、畫面資料變大。

## 什麼時候重新考慮

- 出現看板某一區和畫面資料不一致的 bug，例如選單顯示的組合和看板標題不同。
- 組合選單或已隱藏路線數需要到站資訊，例如在選單裡顯示各組下一班時間。
- 改寫看板畫面的方式，例如改成只依畫面資料整頁重畫。

## 後果

- 改組合選單、名稱下方原因、已隱藏路線數時，改 `app.js` 的 `renderChips()`、`renderHidden()`。
- 新增會改變目前組合或第幾段的操作時，記得呼叫 `renderChips()`。
- 之後的架構檢視與程式審查，在上面的情況出現前不再把這點列為要處理的問題。
